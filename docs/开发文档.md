# CAM-XT (WebCamXT) 开发文档

> 面向 TFT 等新形态器件的测量数据管理与 TCAD 物理模型仿真一体化平台（B/S 架构）
>
> 更新日期：2026-10-19 ｜ 对应提交：`3870083`

## 1. 项目简介

CAM-XT 是一个器件参数分析与仿真 Web 平台，核心能力：

| 能力 | 说明 |
|---|---|
| 测量数据管理 | 上传 `.xls` / `.xlsx` 测量数据，按用户隔离存储，自动解析 W/L/Vgs/Vds 全部组合 |
| I-V 特性绘制 | 输出特性（Id-Vds，固定 Vgs）/ 转移特性（Id-Vgs，固定 Vds），线性/对数坐标，多曲线叠加 |
| 器件参数提取 | 阈值电压 V_th、亚阈值摆幅 SS、场效应迁移率 U_FE 一键提取 |
| TCAD 物理仿真 | 9 项物理参数可调，RC 接触电阻修正，仿真曲线与实验曲线同屏对比 |
| 多用户与权限 | 邀请码注册、JWT 认证、账号有效期管理（默认 30 天，可续期/永久） |
| 操作审计 | 记录用户对文件的全部关键操作（上传/删除/绘图/仿真/拟合/续期） |

双形态交付：**Web 版**（Docker 部署，多用户协作）与**桌面 exe 版**（单机离线，同源内核）。

## 3. 系统架构

```
浏览器 (React SPA, :8080)
   │  /api/* 反向代理
   ▼
nginx (frontend 容器) ──► Flask API (backend 容器, :5000)
                            │
                            ├─ SQLite (instance/tcad.db)
                            ├─ 上传文件 (uploads/<user_id>/)
                            │
                            └─ ComputeService 计算内核
                               （内存 LRU 缓存 ×20, 按文件加锁）
```

**并发模型（关键设计）**

- gunicorn 以 `-w 1 --threads 8` 运行：**单进程多线程**
- 原因：`service_factory` 的 Service 缓存与文件锁都是**进程内存态**，多进程会导致锁失效、缓存重复
- 同一文件的并发请求通过 `locked_service(file_id)` 串行化（仿真会修改 Service 实例字段，如 M / phi_tail / Ntail_eff）
- 仿真前后都会 `reset_fitting_parameters()` 恢复共享实例状态
- 结论：**扩容靠升配单机 CPU（主频），不能简单横向多副本**

## 5. 后端详解

### 5.1 启动流程

`create_app()`（app.py）：

1. 加载 `Config`（环境变量优先）
2. 初始化 db / JWT / CORS（可选）
3. `db.create_all()` + `_migrate_sqlite()`：**轻量迁移**——SQLite 已有表不会自动加列，启动时 `PRAGMA table_info` 检测并 `ALTER TABLE users ADD COLUMN expires_at`（存量用户保持 NULL = 永久）
4. 注册四组路由：auth / admin / file / analysis

### 5.2 数据模型（models.py）

**users**

| 字段 | 类型 | 说明 |
|---|---|---|
| id / username / password_hash / email / role / created_at | — | 基础字段 |
| **expires_at** | DateTime, 可空 | 账号有效期；NULL = 永久；管理员角色不受限 |

**invite_codes**：code / created_by / used_by / expires_at / is_active（一次性邀请码）

**file_records**：user_id / original_filename / stored_path / file_size / md5 / combinations_json（上传时预解析的 W/L 组合与电压列表缓存）/ uploaded_at

**operation_logs**（审计日志，快照存储，删除后仍可读）

| 字段 | 说明 |
|---|---|
| user_id + username | 操作者（用户名快照） |
| file_id + file_name + file_owner_name | 目标文件（文件名/属主快照） |
| action | upload / delete / plot / simulation / auto_fitting / renew |
| detail | 参数摘要，如 `type=output w=100 l=10 rc=True err=0.0052` |

日志写入统一走 `log_operation(user, action, file_record, detail)`，独立事务立即提交。

### 5.3 认证与权限

| 装饰器/函数 | 位置 | 作用 |
|---|---|---|
| `@active_required` | auth.py | JWT 校验 + 账号有效期校验；过期返回 `403 (ACCOUNT_EXPIRED)`，前端据此跳登录页提示续期 |
| `@admin_required` | auth.py | JWT + admin 角色 |
| `get_file_with_ownership(id)` | auth.py | 文件属主校验；**管理员可访问任意用户文件**（审计与代为分析） |

有效期规则：

- 注册即赋 `expires_at = now + 30 天`（`Config.DEFAULT_USER_EXPIRE_DAYS`）
- 续期：`extend_days=N`，未到期则从当前到期时间顺延，已过期则从当下起算
- 永久：`permanent=true` → `expires_at = NULL`
- `admin` 角色豁免有效期（防止锁死管理入口）；登录时同样拦截过期账号

### 5.4 API 一览

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | /api/auth/register | 邀请码 | 注册（默认 30 天有效期） |
| POST | /api/auth/login | 公开 | 登录（过期账号 403） |
| GET | /api/auth/me | 登录 | 当前用户信息 |
| GET | /api/files | 登录 | 文件列表；**管理员返回全部用户文件含 owner_username** |
| POST | /api/upload | 登录 | 上传 xls/xlsx，解析组合并缓存 Service |
| GET/DELETE | /api/files/:id | 属主或管理员 | 文件详情 / 删除 |
| POST | /api/plot-data | 属主或管理员 | 实验曲线（output 固定 Vgs / transfer 固定 Vds） |
| POST | /api/auto_fitting | 属主或管理员 | 参数提取（V_th / SS / U_FE） |
| POST | /api/simulation | 属主或管理员 | TCAD 仿真（可选 RC 修正） |
| GET/POST/DELETE | /api/admin/invites[…] | 管理员 | 邀请码管理 |
| GET | /api/admin/users | 管理员 | 用户列表（含 expires_at / is_expired / file_count） |
| PATCH | /api/admin/users/:id | 管理员 | 改角色 / `extend_days` / `permanent` |
| DELETE | /api/admin/users/:id | 管理员 | 删除用户（级联删文件） |
| GET | /api/admin/logs | 管理员 | 操作日志，分页 + user_id/file_id/action 过滤 |
| GET | /api/health | 公开 | 健康检查 |

### 5.5 计算内核 ComputeService（compute_service.py）

- 列名映射由 `cfg.yaml` 配置：`WName/LName/GateVName/DrainVName/DrainIName/TOName/M_NumName/D_NumName`
- `get_output_data(w, l, type=0, vgs)`：固定栅压取 Id-Vds
- `get_transfer_data(w, l, type=1, vds)`：固定漏压取 Id-Vgs
- `u_fe_computer(w, l)`：二阶导数法提取 V_th，线性区/饱和区 U_FE
- `TCAD_I_simulation(...)`：物理模型仿真（free/tail/deep 三态密度合成，lambertw 求解）
- tail/deep 有效态密度换算（app.py `_do_simulation`）：t>T 时走 `π/sin(πT/t)` 谱展开分支，否则线性修正；输入 g_tail/g_deep 单位 1e18 量级（前端以指数形式显示）

### 5.6 Service 缓存（service_factory.py）

- `_cache`：file_id → ComputeService，LRU 上限 20，超出淘汰最旧
- `_file_locks`：file_id → threading.Lock；**必须先拿锁再取/建 Service**（保证原子性）
- `invalidate(file_id)`：文件删除/用户删除时清理缓存与锁

## 6. 前端详解

### 6.1 路由与页面

| 路由 | 页面 | 守卫 |
|---|---|---|
| /login、/register | 登录 / 注册（邀请码） | — |
| /files | 文件管理；管理员视角显示全部用户文件 + Owner 列 | AuthGuard |
| /analysis/:fileId | 分析页：绘图 / 仿真 / 自动拟合 / 曲线管理 | AuthGuard |
| /admin/invites | 邀请码管理 | AdminGuard |
| /admin/users | 用户管理：角色、**有效期（Renew 弹窗：天数/永久 + 新到期预览）**、删除 | AdminGuard |
| /admin/logs | **操作日志：按用户/动作过滤 + 分页** | AdminGuard |

### 6.2 状态管理（zustand）

- `authStore`：token + user，持久化 localStorage
- `analysisStore`：文件组合信息、选中参数（W/L/Type/V）、曲线列表、拟合结果；`setType()` 切换时自动把 V 选项在 Vgs/Vds 列表间切换（绘图参数面板标签随之联动）

### 6.3 API 层约定（api/client.ts）

- 请求拦截：自动附带 `Authorization: Bearer <token>`
- 响应拦截：
  - `401` → 清登录态跳 /login
  - `403 且 error 含 ACCOUNT_EXPIRED` → 清登录态跳 `/login?expired=1`（登录页提示"账号已过期，请联系管理员续期"）

### 6.4 交互要点

- 态密度 g_tail/g_deep 输入框以指数形式显示（如 `5.1e18`），支持指数输入（`sciFormatter/sciParser`，SimulationDialog.tsx）
- 分析页固定电压标签随曲线类型联动：output → `Vgs:`，transfer → `Vds:`（AnalysisPage.tsx）

## 7. 核心业务流程

```
上传: POST /api/upload
  → 存文件 uploads/<uid>/<fid>_<name>，算 MD5
  → ComputeService 解析 → build_combinations() 生成 w_l_pairs + vgs/vds 映射
  → 存 combinations_json + 预热 Service 缓存 → 记录 upload 日志

绘图: POST /api/plot-data { w, l, type, v_value }
  → locked_service(file_id) 取独占 Service
  → output: get_output_data(w,l,0,v_value)  固定 Vgs 扫 Vds
  → transfer: get_transfer_data(w,l,1,v_value) 固定 Vds 扫 Vgs
  → 记录 plot 日志

仿真: POST /api/simulation { ..., data_params:{t_tail,t_deep,g_tail,g_deep,T,mu_free,Vfb,phi_F0,CoxArea} }
  → locked_service → reset_fitting_parameters()
  → 换算 N_tail/N_deep → (可选) RC 迭代拟合 → TCAD_I_simulation
  → finally reset_fitting_parameters()  ← 无论成败恢复共享状态
  → 记录 simulation 日志（含误差率）
```

## 11. 部署

### 11.1 Docker Compose（推荐）

```bash
cp .env.example .env   # 修改 JWT_SECRET_KEY
docker compose up -d --build
# 访问 http://<host>:8080；首次用 manage.py 建管理员（见下）
```

容器内建管理员（一次性）：

```bash
docker exec -it webcamxt-backend-1 python manage.py create-admin --username admin --password <密码>
```

### 11.2 生产服务器（当前实例）

| 项 | 值 |
|---|---|
| 服务器 | geek@10.102.35.1（SSH 密钥登录） |

